## Findings

1. **R1 — Medium, fix before acceptance: PocketHive login fails through the Vite development UI.** `ui-v2/vite.config.ts:29` publishes `auth-session.js` only as a Rollup build entry. The new `/tcp-mock` development proxy at line 40 serves the TCP UI, whose `tcp-mock-server/src/main/resources/static/auth.js:15` unconditionally imports `/auth-session.js` for POCKETHIVE. Vite development does not expose that build filename: an actual request to its public UI listener returned **200, `text/html`, the SPA index**, with no session exports. Browsers reject that dynamic module import, so the configured PocketHive provider cannot initialize there. Serve the same canonical session module at the stable URL in development too; do not duplicate session parsing or introduce a provider fallback. Verify the served JavaScript content/module exports, not just build output. Production Nginx/build delivery does have the asset; this finding is specifically the development path introduced here.

2. **R2 — Medium, architecture acceptance blocker: processor profile discovery still belongs partly to AuthRuntime.** `common/worker-sdk/src/main/java/io/pockethive/worker/sdk/auth/AuthRuntime.java:121–128` constructs the profile path, performs `Files.isRegularFile`, and decides the missing-profile outcome. This is exercised by `TcpProtocolHandler` and `Iso8583ProtocolHandler` through `forApplications`. `RESP-WORK-AUTH-RUNTIME` and `RESP-WORK-AUTH-PROFILE-LOADING` assign discovery to `AuthProfileLoader`; the loader owns template discovery but leaves this active processor discovery path in its caller. Complete the transfer by moving processor path resolution/probing and the corresponding missing-profile failure into the loader. Preserve existing discovery precedence and error behavior. This is an incomplete boundary transfer, not evidence of a second token store or a new runtime regression; the repository workflow blocks acceptance on architecture/code disagreement.

3. **R3 — Low: new shared-session header has a dead contract anchor.** `ui-v2/src/lib/authSession.ts:4` links to `#pockethive-authentication-and-ownership`, while the contract heading is `Authentication provider and ownership` (`#authentication-provider-and-ownership`). Correct the reference so the canonical contract can be reached from its owner.

No additional critical duplicate authority was established in the reviewed slice. This statement does not certify unrelated services or deferred native TCP work.
