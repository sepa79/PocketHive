# Local intake qualification

These checks exercise the public Python CLI and packaged files. They do not
qualify a Codex, Amazon Q, or Copilot version, MCP connectivity, runtime bundle
semantics, or a deployed PocketHive environment. No backend ports are used.

Run from the installed skill directory after its maintainer has finalised the
package manifest:

```sh
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
```

## Checks

| Risk | Required observable result |
| --- | --- |
| Blank or partial client input | Draft remains usable; missing material facts remain gaps; handoff is blocked. |
| Template defaults or sample pollution | Fictional targets and approvals do not become sourced client facts. |
| Forged approval | A populated approval flag without qualifying provenance cannot enable handoff. |
| Duplicate keys or executable YAML tags | Parsing fails visibly before document mutation or execution. |
| Changed source bytes | Old source hashes and confirmations are rejected. |
| Duplicate question state | Requirements question projection is derived from traceability; conflicts fail or are explicitly regenerated by its owner. |
| Cyclic or stale document hashes | Finalisation binds actual bytes in the declared order; no self hash or false source digest. |
| Fragmented bundle | Relevant source files and exact observations remain traceable; expressions and unselected contexts stay unresolved. |
| Misleading role/transport names | Custom worker capabilities and transport are not guessed from role, filename or neighbouring declarations. |
| Source scripts and dependency files | They appear only as source data and never execute; no test marker is created. |
| Missing or changed package resources | Mandatory template/manifest/dependency verification fails; no reconstructed substitute. |
| Relocated offline ZIP | Public CLI works from extracted package outside the repository with `python -I -S`, no `PYTHONPATH` or site packages. |
| Unsafe package entries | Symlink escapes, absolute paths and parent traversal are excluded or rejected; package creation never reads unrelated files. |

The executable suite records actual command results. Client-specific skill
discovery, attachment loading, interactive questions and asynchronous resume
remain separate manual qualification gates, even when this suite passes.

## Recorded local result — 1.0.0, 2026-09-16

The final expanded suite passed **54 distinct tests** using Python 3.12.3 on
Linux. Command from the PocketHive repository root:

```sh
python3 -B -I -S -m unittest discover -s .agents/skills/pockethive-intake/tests -v
```

The run completed in 82.533 seconds. It included both intake modes from an
extracted ZIP under a path containing spaces. An audit hook rejected original
repository reads, network/DNS operations and child processes; Python site
packages and PYTHONPATH were unavailable. Two archive builds had identical
bytes. The positive synthetic handoff retained unknown production context and
unexecuted results; incomplete and contradictory inputs remained visible.

A read-only smoke check of the repository's `local-rest-topology` bundle
inventoried two files and one supported literal observation. Draft validation
had no errors and 31 gaps; handoff correctly remained incomplete. Source bytes
were unchanged.

After consolidating the remaining issue-object construction under its shared
owner, the affected 21 CLI tests and three readiness tests passed again. The
release ZIP also passed an extracted-package smoke check for both modes and
explicit rejection of a wrong template version.

Source hashes, local Markdown links, skill frontmatter, Python syntax and
whitespace were also checked. Final archive integrity and a SHA-256 sidecar
identify the distributable bytes. These are local development results.

Python 3.10 is the declared minimum, but this run used 3.12.3. Other Python/OS
combinations and actual Codex, Amazon Q and Copilot clients remain unqualified.
No runtime bundle validation, authentication, load test, client interview or
human assessment of source faithfulness was performed by this automated suite.

## Amazon Q feedback regressions — 1.1.0, 2026-09-16

The user-reported missing-projection failure was reproduced against the
committed 1.0.0 package: `finalise` returned `COMMAND_FAILED` after removal of
`openQuestions` with a null prior digest. The 1.1.0 public-CLI tests verify:

- Raw working templates and removed projections finalise repeatedly without
  changing output bytes; independent authored questions are not discarded.
- Schema/projection failures retain document/pointer context. Schema errors
  identify constraints and expected versions; root pointers stay empty.
- `--debug` before or after a subcommand keeps stdout as one JSON object and
  writes safe diagnostics to stderr. Injected exception text and real YAML
  parser content do not leak; unexpected failures expose their exception type.
- Explicit HTTP observation population retains provenance, user values and
  source identity. Conflicts and duplicate identities fail before writes;
  missing containers have exact pointers. Repeated population is byte-stable.
- Correlation bindings resolve step-local definitions for exact repeated API
  occurrences. Unknown, forward, self, duplicate and orphan references fail;
  incomplete settings remain gaps. Plan version 4 receives an explicit
  version error for the new version 5 representation.

All **89 tests passed in 132.512 seconds** using Python 3.12.3 on Linux. The
suite ran from an extracted ZIP in Bubblewrap with external networking disabled,
the host home/repository absent, the package read-only and site packages
unavailable. The isolation probe passed. This includes the existing 54 checks
and 35 additional tests; there is no coverage or throughput claim.
